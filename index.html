Declarative lane

Validated JSON describes the UI tree, state, lists, forms, and transitions. No code runs, so strict and balanced profiles and MCP Apps accept it.

Render this sample in the Playground
App.jsx
import { useState } from "react";

const DATA = {
  Revenue: [42, 58, 51, 74, 69, 88],
  Users: [24, 31, 45, 39, 52, 61],
  Latency: [80, 64, 58, 49, 44, 38],
};

export default function App() {
  const [metric, setMetric] = useState("Revenue");
  const values = DATA[metric];
  const max = Math.max(...values);

  return (
    <main style={{ padding: 28, fontFamily: "system-ui, sans-serif" }}>
      <h2 style={{ margin: 0 }}>Weekly {metric.toLowerCase()}</h2>
      <div style={{ display: "flex", gap: 8, margin: "16px 0 24px" }}>
        {Object.keys(DATA).map((name) => (
          <button
            key={name}
            onClick={() => setMetric(name)}
            style={{
              padding: "6px 14px",
              border: 0,
              borderRadius: 999,
              background: name === metric ? "#0b5cfa" : "#eef2ff",
              color: name === metric ? "#ffffff" : "#1e293b",
            }}
          >
            {name}
          </button>
        ))}
      </div>
      <div style={{ display: "flex", alignItems: "flex-end", gap: 10, height: 150 }}>
        {values.map((value, index) => (
          <div
            key={index}
            style={{
              flex: 1,
              height: `${(value / max) * 100}%`,
              borderRadius: 8,
              background: "linear-gradient(#00d4fb, #0b5cfa 55%, #8a2bf9)",
              transition: "height 300ms ease",
            }}
          />
        ))}
      </div>
    </main>
  );
}

Why Renderify

Everything between generated code and interactive UI

A small, security-governed runtime with explicit contracts at every boundary, from module resolution to the trust lane a plan runs in.

Zero-build rendering

Generated JSX/TSX is transpiled in the browser with @babel/standalone and its imports resolve through JSPM. No backend compiler, no deploy step, no server round-trip.

import { renderPlanInBrowser } from "renderify";

await renderPlanInBrowser(plan, { target: "#mount" });

Packages

Composable by design

Start with the SDK, or assemble only the layers you need. Every package is published to npm under the MIT license.

  • SDKrenderifyThe recommended entry point: an app factory, one-shot helpers, and re-exports of the core, runtime, and provider APIs.
  • React@renderify/reactRenderifyView for validated plans, RenderifyFrame for sandboxed model-written JSX, and the useRenderifySession hook.
  • Contracts@renderify/irThe RuntimePlan schema, node, state, and action types, guards, and shared constants.
  • Execution@renderify/runtimeExecutes plans and source modules, resolves JSPM imports, and renders to HTML or browser targets.
  • Sandbox@renderify/frameAn opaque-origin iframe for model-written JSX/TSX with a strict CSP, an action allowlist, loop guards, and a watchdog.
  • Policy@renderify/securityValidates plans, capabilities, module sources, and runtime source before anything executes.
  • Orchestration@renderify/coreWires config, LLM, code generation, policy, runtime, and UI rendering together through RenderifyApp.
  • Providers@renderify/llmOpenAI, OpenAI Codex, Anthropic, Google, Ollama, and LM Studio interpreters, plus a provider registry.
  • Tooling@renderify/cliRun prompts, inspect RuntimePlan JSON, probe dependencies, execute plan files, and open the playground.
  • Integration@renderify/mcp-appAn offline, declarative RuntimePlan adapter that serves a self-contained ui:// resource for MCP Apps.

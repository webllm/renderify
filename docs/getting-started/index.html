Getting Started

Renderify renders UI that a model describes. A model (or your code) produces a RuntimePlan, a JSON description of interactive UI with state, lists, forms, and events; Renderify validates it, checks it against a security policy, and renders it. When a plan is not enough and the model writes JSX, Renderify runs that code in a sandboxed iframe instead of your page.

Install

Server-side packages require Node.js 22 or newer.

Render a plan in React

<RenderifyView> checks the plan against the balanced security profile, renders it, and runs its transitions locally. Plans can also loop over arrays, render conditionally, and bind form fields to state; see the RuntimePlan IR reference.

Render without React

For a one-off static render, use renderPlanInBrowser(plan, { target: "#app" }).

Let your model produce plans

Give your model a render_ui tool whose input is a RuntimePlan, and render the tool result with <RenderifyView>. @renderify/ir provides the JSON Schema, validation with repair messages, and prompt guidance. The integrations guide shows the Vercel AI SDK, CopilotKit, assistant-ui, and AG-UI, and the Next.js chat template is a working app.

Run model-written JSX safely

The code runs in an opaque-origin sandboxed frame: it can use npm packages from JSPM, but it cannot read your page, and only the action types you allow reach your app.

Serve UIs from an MCP server

@renderify/mcp-app turns tool results into interactive views in MCP Apps hosts. Start from the MCP server template.

Try it without code

The website Playground renders JSX/TSX or RuntimePlan JSON in your browser with no model and no account.

Renderify's own prompt-to-UI pipeline

If you do not use an agent framework, @renderify/core and @renderify/llm run the whole loop: prompt, structured generation with repair, policy checks, and rendering.

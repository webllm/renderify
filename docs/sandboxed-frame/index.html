Sandboxed frame

@renderify/frame runs untrusted UI code, such as JSX a model just wrote, in an <iframe sandbox="allow-scripts"> with an opaque origin. The code renders and stays interactive, but it cannot read your page, cookies, or storage, and it talks to your page only through actions you allow.

Use it when declarative RuntimePlans are not enough: npm libraries, custom components, or anything you would otherwise have to run with the trusted profile. The website Playground uses the same frame.

Quick start

render also accepts a RuntimePlan: frame.render({ plan }). Declarative events such as onClick: "save" become actions too.

What the frame guarantees

PropertyHow
No access to the host pagesandbox="allow-scripts" without allow-same-origin gives the content an opaque origin.
Limited networkThe frame's CSP allows scripts and requests only to the runner's origin and the module CDNs (ga.jspm.io, cdn.jspm.io, esm.sh by default). Frames, workers, form submission, and <base> are blocked.
Private channelThe host connects with a transferred MessagePort. The runner accepts a connection only from its parent window, and only once.
Explicit host actionsContent calls window.renderify.action(type, payload). Only types in allowedActions reach onAction; others go to onBlockedAction. Payloads are JSON, at most 64 KiB.
Recovers from hangsSynchronous loops get a time check (loopTimeoutMs, 1.5 s by default) that throws instead of freezing the page. A render that exceeds timeoutMs (45 s) rejects with code timeout and the iframe is replaced.
Tamper-evident runnerThe default runner URL is pinned to the package version and loaded with Subresource Integrity.

The frame cannot stop content from misleading users inside its own rectangle, and code can leak data you give it through module CDN request URLs. Do not pass secrets into a frame. See ADR-0002 and the threat model.

render rejects with a RenderifyFrameError whose code is timeout, superseded (a newer render started), reset, disposed, boot-failed, render-failed, or invalid-input. Errors inside rendered components are reported as error diagnostics on a successful result, the same way the runtime reports them elsewhere.

renderSandboxedSource(container, source, options) is a shortcut that creates a frame and renders one module.

Self-hosting the runner

The runner (@renderify/frame/runner.js, about 2.6 MB with Babel and the runtime; runner-plan.js is about 200 KB without Babel) is the only script that runs inside the frame. To avoid loading it from jsDelivr, copy it to your static assets and pass its URL:

Because the frame's origin is opaque, a script loaded with runnerIntegrity is a cross-origin request: serve it with Access-Control-Allow-Origin: *.

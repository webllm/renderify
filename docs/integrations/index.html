Integrations

Agent frameworks already move tool calls and results between your model and your UI. Renderify fits at the end of that pipe: a tool returns a RuntimePlan, and your client renders it with <RenderifyView> from @renderify/react. Plans are JSON, so they survive any transport, and they are validated and policy-checked before they render.

All examples use one server-side tool, render_ui, whose input is a RuntimePlan. Give the model the shared schema and repair errors from @renderify/ir:

Add RUNTIME_PLAN_INTERACTION_GUIDANCE to your system prompt so the model knows how to express lists, conditions, forms, and events.

MCP Apps

MCP servers can return plans that hosts render in a sandboxed view, with no client code at all. Use @renderify/mcp-app; the MCP server template is a working task board whose form and buttons call allowlisted server tools. To let the model write JSX instead, register the app with sourceMode: true; the view then renders source in a sandboxed frame nested inside it (details).

Model-written source

When a plan is not expressive enough and the model writes JSX, render it with <RenderifyFrame source={code} /> instead of <RenderifyView>. It runs the code in an opaque-origin sandboxed frame, and only the action types you allow reach your app.

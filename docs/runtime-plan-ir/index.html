RuntimePlan IR Reference

The RuntimePlan is the intermediate representation (IR) at the heart of Renderify. Every piece of UI that Renderify renders — whether generated by an LLM, authored by hand, or loaded from a file — is expressed as a RuntimePlan.

RuntimePlan Structure

Required Fields

  • id — non-empty string identifying the plan. Used for state management and caching.
  • version — positive integer. Must be >= 1.
  • root — the top-level node of the UI tree.
  • capabilities — declares what the plan needs (even if empty {}).

Spec Version

The specVersion field declares the protocol contract. Currently the only version is "runtime-plan/v1". In strict and balanced security profiles, this field is required.

Node Types

The UI tree is composed of five node types: text, element, and component render content, while each and if repeat or conditionally render their children.

Text Node

Template interpolation resolves {{state.count}}, {{context.userId}}, {{vars.name}} at render time.

Element Node

Props support standard HTML attributes. Event handlers use the onClick, onInput format and are converted to runtime event bindings; see Events and forms.

Component Node

Component nodes reference external modules loaded via the JSPM module loader. The module specifier is resolved through the module manifest or JSPM CDN.

The referenced export is invoked as a Renderify component factory and must return a RuntimeNode tree or a string. Component nodes are not React or Preact component hosts.

Each Node

Children are rendered once per array item, in place: an each inside a ul produces li siblings without a wrapper element. Inside the loop, templates and props can read the loop variables, such as {{todo.title}} and {{index}}. Loops nest, and inner loops can read outer variables. as and index must be simple identifiers other than state, event, context, and vars.

With key, each element produced by an iteration gets a stable key, so removing or reordering items reuses the right DOM nodes (and keeps focus and checkbox state on the right row). A single render may produce at most 10,000 nodes through each; beyond that, rendering stops and the runtime reports RUNTIME_EACH_LIMIT_EXCEEDED.

If Node

Without equals, children render when the value is truthy. Truthiness follows JavaScript except that an empty array is false, so "when": "state.todos" means "has todos". With equals, primitives compare by their text form (2 equals "2"), and string values may be templates such as "{{item.id}}". Use two if nodes, one with "not": true, for if/else.

A control node in the plan root renders inside a <div data-renderify-fragment style="display:contents"> wrapper so it does not affect layout.

Execution Profiles

Execution Budgets

Three budget dimensions are enforced at runtime:

BudgetFieldDescription
Import countmaxImportsDeclared imports and distinct remote materializations
Component invocationsmaxComponentInvocationsNumber of component renders
Wall-clock timemaxExecutionMsTotal execution time in milliseconds

maxImports covers declared imports and remote modules reached transitively through component or runtime-source imports during the same execution. When a budget is exceeded, execution stops and a diagnostic error is emitted.

Value References

The $from syntax references values from other contexts:

References may appear anywhere inside a set or push value, so a new list item can combine bound state and literals:

Event binding payloads may contain references too. They are resolved against state when the event is handled, after earlier events in the same interaction have been applied, so the payload always carries what the user just entered. A payload that is a single reference, such as { "$from": "state.form" }, becomes the referenced object.

Events and forms

Element props named on + an event (onClick, onInput, onChange, onKeyDown, ...) dispatch a runtime event. The value is either a transition name or { "type": "...", "payload": { ... } }. Inside each, payload templates such as "{{index}}" capture the current item:

onEnter dispatches when Enter is pressed in a field (without modifier keys or an active IME composition) and suppresses the newline.

Events from input, textarea, and select elements carry the control's live value in event.payload.value: a boolean for checkboxes (with event.payload.checked), a number for number and range inputs, an array for multi-selects, and a string otherwise. Keys declared in the binding's payload take precedence over captured values.

Bound controls

bind keeps a form control and a state path in sync without writing transitions:

The control shows the state value, and each edit writes back to the path (text-like controls on input, checkboxes, radios, and selects on change) through a renderify:bind runtime event before any transitions run. Checkboxes bind booleans; a radio is checked when the bound value equals its value; number inputs bind numbers. The state. prefix is optional, and loop templates in the path are resolved per item.

When state changes the bound value, for example when an "Add" transition clears draft, the control updates even if the user already edited it. A focused control is only updated when it is being cleared, so renders never overwrite text while the user is typing.

Password and file inputs are never bound and never captured, so their contents cannot reach plan state, events, or a host's model context.

Forms

A form element renders as an inert <div data-renderify-form> container without action, method, or target, so it can never navigate the page or post fields anywhere. The runtime emulates submission instead: onSubmit fires when a submit button inside the form is clicked or Enter is pressed in one of its text fields. The payload contains the form's named fields, merged under any declared payload keys:

Submitting this form dispatches tool:search_flights with { "from": "...", "to": "..." }. A lone checkbox is a boolean, same-named checkboxes are the array of checked values, and a radio group is the checked value or null. Disabled, password, and file fields are skipped. Fields keep what the user typed after a submit; bind them when a transition should clear them.

Path Safety

All state paths are validated against prototype pollution. The following segments are rejected:

  • __proto__
  • prototype
  • constructor

Module Manifest

The manifest provides deterministic module resolution. In strict security profile, bare specifiers (like "recharts") must have a manifest entry. In strict mode, remote modules must also include integrity hashes.

Source Module

Source modules enable richer interactivity than the declarative node tree. The source code is transpiled via Babel, imports are rewritten to browser-resolvable URLs, and the default export is rendered as a Preact component (when runtime: "preact") or as a RuntimeNode tree.

  • runtime: "renderify" expects the exported function to return RuntimeNode | string and can participate in the declarative execution/sandbox model.
  • runtime: "preact" expects a Preact-compatible component and should be rendered with renderTrustedPlanInBrowser or the trusted security profile.
  • runtime: "preact" does not run inside the browser worker/iframe/ShadowRealm sandbox adapters.
